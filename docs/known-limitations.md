# Known limitations

StoreAI is a reference architecture, not a turnkey production system. This document consolidates the
known limitations noted across the other docs so you can weigh them before adapting the project.

| Area | Limitation | Impact | Reference |
|------|------------|--------|-----------|
| Try-on code paths | Try-on is generated by two code paths (the streaming-chat `_exec_vton_direct` and the REST `/virtual_try_on` endpoint), with an older bypassed implementation in `tryon-mcp`. | Duplicated logic; consolidation is tracked follow-up work. Behavior matches because both use the shared `vton_engines`/`vton_verify`. | [architecture.md](architecture.md#try-on-code-paths-known-duplication) |
| Conversation state | The LangGraph in-flight conversation state uses an in-memory checkpointer (`MemorySaver`) by default. | In-flight graph state is lost on pod restart. Chat **history** persists separately in DynamoDB and reloads on sign-in. | [security.md](security.md) |
| Chat model tool-calling | Weaker chat models (Claude Haiku, self-hosted Qwen3-8B) sometimes claim success in text without calling the try-on tool. | No image is generated and the reply returns in ~1–2s instead of ~15–40s. Use Claude Sonnet for reliable agentic try-on. | [troubleshooting.md](troubleshooting.md) |
| Edge protection | No AWS WAF or rate limiting in front of CloudFront in the demo. | No protection against abusive or high-volume traffic. Add WAF + rate limiting before production. | [security.md](security.md) |
| Networking (HA) | A single NAT gateway provides outbound egress. | Not highly available; a single-AZ NAT failure interrupts egress. Acceptable for a demo, not for production. | [architecture.md](architecture.md#network-topology) |
| Credentials | The Cognito sign-in user ships with a permanent demo password, and CORS allows all origins. | Insecure defaults intended for a smooth first run. Change both before any non-demo use. | [security.md](security.md#review-before-non-demo-use) |
| Container & infra hardening | Model servers run as root with a writable filesystem; no per-pod NetworkPolicies; SSE-S3 (not KMS-CMK); no S3 access logging / DynamoDB PITR / VPC flow logs / ECR scan-on-push in the demo. | Accepted demo tradeoffs. Review before production. | [security.md](security.md#review-before-non-demo-use) |
| Self-hosted try-on (Qwen) | `diffusers` is pinned to `0.36.0` for `QwenImageEditPlusPipeline` compatibility. | A known advisory (CVE-2026-44513) is fixed in `0.38`; not exploitable here (only trusted, locally-compiled models are loaded). Move to `0.38` for production (requires a Trainium recompile). | [self-hosted-models.md](self-hosted-models.md) |

For the reasoning behind these design choices, see [design-decisions.md](design-decisions.md).
